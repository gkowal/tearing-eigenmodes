# Tearing Eigenmodes

Utilities for analyzing tearing instability eigenmodes using the `psecas` pseudospectral solver.

## Architecture & Module Responsibilities

The project is structured into several specialized modules:

- **`solver.py`**: The central orchestrator. It integrates the grid setup, the `psecas` system definition (Classical or Gyrotropic MHD), and the iterative solver.
- **`analysis.py`**: Contains diagnostic functions for post-processing eigenmodes, such as calculating the inner-layer thickness (`inner_layer_thickness`) and finding peak locations.
- **`grid.py`**: Logic for automated resolution ($N$) and scaling ($C$) determination via `select_NC` to ensure the tearing layer is adequately resolved.
- **`parser.py`**: CLI argument parsing and unified parameter dictionary (`params`) construction.
- **`io.py`**: Handles persistence of results to `.npz` (state) and `.dat` (summary) files.
- **`refinement.py`**: Provides heuristic functions to improve initial guesses for parameter sweeps based on previously computed results.
- **`physics.py`**: Physical constants, Equation of State (EOS) index calculations, and physics-based maximum growth rate estimation (`estimate_max`).
- **`logging_utils.py`**: Custom logging setup including `SmartStreamHandler` for interactive progress updates and file logging.
- **`printing.py`**: Functions for pretty-printing simulation parameters and status information.

## Execution

The project includes CLI scripts for running calculations and visualizing results:

- **`scripts/eigenmodes-compute.py`**: Calculates the dispersion relation (growth rate vs. wavenumber) for a given set of parameters.
- **`scripts/eigenmodes-maxima.py`**: Finds the maximum growth rate and its corresponding wavenumber across a range of a specified parameter (e.g., S, Pr, β).
- **`scripts/eigenmodes-profiles.py`**: Visualizes the eigenfunctions (e.g., $\delta u_z, \delta B_z$) from saved `.npz` state files.
- **`scripts/eigenmodes-maps.py`**: Reconstructs and plots 2D color maps (in the XZ plane) of the eigenfunctions from saved `.npz` state files.


These scripts should be run from the project root. It is recommended to install the package in editable mode (`pip install -e .`) to ensure the scripts can correctly import the `tearing_eigenmodes` library.

> [!IMPORTANT]
> Always use the Python environment in `~/.venv/` (e.g., `~/.venv/bin/python`) for executing scripts, running tests, or when checking package availability.


### Persistence and Resuming
By default, the scripts save state in the `RESULTS/` directory. If a calculation is interrupted or rerun with the same parameters, the scripts will resume from the existing `.npz` files.
- **Atomic Updates**: State saving is atomic. The scripts write to a temporary file first and use `os.replace()` to update the final `.npz` file, preventing file corruption during interruptions.
- To start from scratch, remove the `RESULTS/` directory: `rm -rf RESULTS/`.
- To overwrite existing results without deleting the directory, use the `--force` (or `-f`) flag.

## Key Conventions

### Attribute Safety
When accessing physical parameters on the `system` object (e.g., in `analysis.py`), always use `getattr` with a sensible default. This ensures compatibility between different MHD models (e.g., `TearingClassicalMHD` vs `TearingGyrotropicMHD`) which may not share all attributes like `shear` or `w`.

### Layer Analysis Return Signatures
To maintain consistency across the solver and I/O modules, adhere to the following return orders:

- **`inner_layer_thickness()`**: `(δin, nin, nwa)`
- **`eigenmodes()`**: `(σ, s, e, δin, nin, nwa, C, N, grid_zg, success_flag)`
- **`load_eigenmodes()`**: `(v, α, σ, e, δ, c, nin, nwa, N)`

### Data Output
- **`.npz` files**: Store the full state of a specific eigenmode calculation, including eigenfunctions and metadata.
- **`.dat` files**: Summary tables generated by `write_results()`. The standard columns are:
  - Dispersion runs: `α, Re(σ), Im(σ), δ_in, tolerance, C, n_in, n_wa, N`
  - Dependence runs: `[param], α_max, Re(σ_max), Im(σ_max), δ_in, tolerance, C, n_in, n_wa, N`

## Logging

The project uses a centralized logging system managed by `logging_utils.setup_logging()`:

- **Library Code**: Modules in `src/tearing_eigenmodes/` use module-level loggers (`logging.getLogger(__name__)`).
- **Scripts**: Entry points in `scripts/` configure logging via `setup_logging()`.
- **SmartStreamHandler**: A custom handler that handles `\r` (carriage return) correctly, allowing progress updates to stay on the same line without messing up the log history.
- **Verbosity**: Use the `--verbose` (or `-v`) flag to set the log level to `DEBUG`. Otherwise, the level defaults to `INFO`.
- **Log Files**: Use `--log-file [PATH]` to save detailed `DEBUG` logs (with timestamps) to a file while keeping the console output clean.

## Automated Grid Scaling
The project relies on `grid.select_NC` to automatically determine the optimal scaling factor $C$ and resolution $N$. It balances the need to resolve the inner layer ($z \approx 0$) with the requirement to capture the outer decay of the eigenmode. The parameter `n_inner` (minimum points in the layer) and `decay_efolds` (resolution at $z_{max}$) are the primary controls for this logic.
